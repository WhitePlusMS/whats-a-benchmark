## Product Overview

**One-liner:** 面向中文读者的 AI 与大模型评测资料库，帮助大家看懂模型发布报告里的任务与分数。

**What it does:** 「what's a benchmark? · 到底测什么？」围绕每项评测整理任务说明、可公开样例、评分方法、版本关系和官方来源。读者可以查找评测名称、查看具体任务，并排比较两到三项评测的条件与局限。

**Product category:** AI 评测资料库、评测阅读工具。

**Product type:** 公开网页资料站；界面与本站解读使用简体中文，原始任务保留来源语言，无需登录即可阅读。

**Business model:** 当前材料未确认收费或商业化模式；公开文稿不写订阅、付费服务或商业承诺。

**Product boundaries:** 不执行模型评测、不调用模型 API 生成成绩、不生成统一模型排行榜。样例展示范围取决于公开程度、来源与许可，不能承诺所有原题均可在站内查看。

**Website:** https://whiteplusms.github.io/whats-a-benchmark

**Repository:** https://github.com/WhitePlusMS/whats-a-benchmark

## Target Audience

以下为基于现有流程提出的目标读者，尚未验证实际用户分布。

**Primary audience:** 阅读模型发布报告、希望理解评测名称和分数含义的中文 AI 使用者。

**Secondary audience:** 核对评测任务与条件的开发者、产品人员，以及整理 AI 技术资料的作者和学习者。

**Target companies / Decision-makers:** 当前是开放阅读场景，不建立企业采购角色或企业规模假设。

**Primary use case:** 阅读模型报告时，从陌生名称进入任务说明，理解评测考察的能力、评分条件与结果适用范围。

**Jobs to be done:**

- 理解模型在一项评测中实际接收什么、需要完成什么。
- 比较评测任务、指标和版本，核对两份结果是否具备可比较的条件。
- 找到官方定义、数据入口与原始资料，继续查阅或引用。

**Use cases:** 粘贴报告中的一组名称；从能力分类进入目录；查看样例与参考答案；比较两到三项相关评测并分享链接。

## Problems & Pain Points

以下为依据产品流程提出的阅读问题，不是用户反馈或访谈结论。

**Core problem:** 仅凭评测名称与分数，无法完整了解任务内容、评分方式和比较条件。

**Reading friction:** 模型报告、论文与数据说明需要分别查阅；同一评测家族的原版、子集与衍生版本需要核对；可公开题目、节选、本站解读与受限原题需要分清。

**What it costs them:** 可能增加寻找资料与核对条件的步骤；没有实测耗时，不宣传节省比例。

**Emotional tension:** 尚无访谈证据，不描述普遍焦虑或共同感受。

## Competitive Landscape

尚未开展系统竞品调研，不作第三方产品的能力优劣判断。

**Direct:** 暂无经过核实的竞品清单。

**Secondary:** 分别阅读官方论文、项目主页和数据说明，能够获得一手信息；本站提供中文整理与统一阅读入口。

**Indirect:** 直接浏览模型报告与排行榜，能够查看对应成绩；本站补充对任务、指标和条件的解释。

## Differentiation

卖点描述现有内容组织方式，不声称竞品均不具备这些能力。

**Key differentiators:**

- **用任务解释能力：** 输入输出与可公开样例放在具体条目中，帮助读者理解模型需要完成什么。
- **连同条件阅读分数：** 指标、运行要求、局限和版本关系一起展示，支持两到三项评测横向比较。
- **保留资料出处：** 官方来源与本站解释分别标注，读者可以继续核对原始资料。

**How we do it differently:** 以评测条目为阅读单位，按共同栏目组织任务、样例、指标、关系与来源，提供搜索、筛选、批量查询和分享入口。

**Why that's useful:** 理解任务后可以继续核对评分和来源，减少寻找不同资料之间对应关系的步骤。

**Why readers choose us:** 尚未收集实际选择原因；公开文案不写用户喜爱、行业认可或替代其他产品的结论。

## Objections

以下为基于产品边界准备的问题，不是已收集的用户异议。

| 可能的问题                 | 依据现有功能的回答                                             |
| -------------------------- | -------------------------------------------------------------- |
| 能否直接得到模型排名？     | 可以理解任务与评分；模型成绩请查看原始报告与榜单。             |
| 每项评测是否都有完整原题？ | 展示取决于公开程度与许可；受限条目说明获取方式并提供官方入口。 |
| 分数能否直接代表业务效果？ | 条目说明评测条件和局限；实际业务仍需要对应场景的验证。         |

**Anti-persona:** 主要需要自动运行评测、调用模型 API、下载全部题库或获得统一模型选购排名的使用者，当前产品无法直接满足这些需求。

## Switching Dynamics

以下为阅读习惯的工作假设，尚未做用户验证。

**Push:** 需要反复在报告与评测资料之间核对名称、版本和指标。

**Pull:** 中文解释、可公开样例、结构化详情、横向对比与官方来源入口。

**Habit:** 继续阅读熟悉的原始报告与资料收藏。

**Anxiety:** 需要确认整理是否准确、是否保留来源、是否分清本站解释与原始内容。文案直接说明来源与展示边界。

## Customer Language

**How readers describe the problem / How readers describe us:** 暂无访谈原话与用户评价，不编造引语、推荐或口碑。

**Words to use:** 任务、输入输出、可公开样例、评分方法、评测条件、版本关系、官方来源、中文资料库。

**Words to avoid:** 最全面、权威排名、一键选出最强模型、全部真实原题、行业首创、实时更新、用户一致好评。

| 术语     | 本项目中的含义                                                                               |
| -------- | -------------------------------------------------------------------------------------------- |
| 评测     | 包含任务、数据、执行条件与评分规则的评价方式；条目可能是原版、子集、衍生版、体系或内部评测。 |
| 样例     | 用于说明任务的站内记录，包含原始材料、节选与明确标注的本站解读。                             |
| 横向对比 | 比较评测的任务、指标、条件、版本与局限，不是比较模型成绩。                                   |
| 来源     | 支持具体说明的官方论文、项目主页、仓库、数据说明或模型发布资料。                             |

## Brand Voice

**Tone:** 按 oil-tone 使用平实、完整、能够自然朗读的中文，说明具体用途与依据。

**Style:** 面向读者自然使用「我们」或「大家」；介绍作者已经证实的行为时才使用「我」。避免虚构开发起因、个人经历与用户反馈。

**Personality:** 清楚、克制、具体、便于核对。

**Visual direction:** 复用正式题卡对号标识，默认深蓝 `#092D56` 与橙色 `#F58A08`。站内题卡跟随七种主题色，对号固定橙色；独立品牌素材和中英文封面保持蓝橙配色。封面用 HumanEval/0 题目节选与 pass@k 说明任务、样例和评分，配图使用真实目录、案例、手机与主题界面，不绘制虚构跑分或模型排名。

## Goals

**Primary goal:** 让首次访问的读者理解用途，并查看一项与当前报告或任务有关的评测。

**Conversion action:** 打开网站 → 搜索或选择分类 → 阅读详情与样例 → 按需比较或访问官方来源。

**Secondary action:** 通过 GitHub Issues 提供带有官方来源的纠正或补充。

**Current metrics:** 未提供访问量、留存、转化率或增长目标，不编造数据。
