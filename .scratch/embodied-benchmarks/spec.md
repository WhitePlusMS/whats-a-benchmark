# 具身智能评测专区：实施说明

状态：规划完成，尚未实施。范围为在现有网站增加独立的具身智能专区及相应评测资料，不执行机器人评测，不声称真机验收。

## 已确定的产品要求

1. 顶部导航增加“具身智能”入口，与现有评测目录并列。专区首页参考现有 LLM 目录的结构、分类筛选、搜索、卡片、响应式布局和主题，不创建另一套前端视觉系统。
2. 按任务能力组织评测；一个评测可归入多个任务分类，仍维护同一条内容和同一个详情地址。专区只按任务能力筛选，不增加仿真/真机或机器人类型筛选。
3. 仿真或真机、机器人、输入观察、输出动作、目标、评分和成功条件等根据官方资料放在详情页，资料未公开或尚未核实须如实标明。一个评测可能有多种环境或机器人，不强行压成唯一值。
4. 样例卡片选择“过程优先”，以可核实的任务过程帮助理解；现有样例查看器和图片、视频、原始数据等组件优先复用。不得为凑格式舍弃更合适的内容。
5. 数据集、模拟器、比赛等资源在详情页明确类型并关联官方资料；不同评测版本、衍生版本、子集或年度挑战如范围或协议有实质差异，应分别收录、标明关系，不能以新版本覆盖旧版本。

## 首页和分类

- 保留现有目录功能和原有分类；专区拥有单独入口和领域内任务分类，但不复制 benchmark 实体或凭新增分类推断模型成绩。
- 首批任务分类作为整理线索：抓取与操作、导航与移动、双臂协作、长步骤任务、具身推理。分类允许交叉；各名称、定义及候选归属须以逐项资料核对结果为准，可补充合适分类，不因为预设五项而丢失能力类型。
- 搜索、分类筛选、卡片与详情入口沿用现有目录的交互及样式。分类计数是匹配到该分类的独立评测数量；交叉分类的计数相加不等于评测总数。默认不增加平台类型等额外筛选。
- 当前 `category` 是单字符串，现有筛选、分组及计数按单值比较。实现时须在现有内容模型中增加有严格校验的具身任务分类多值表达，并修改专区筛选、统计和分组；不以复制多条数据或多个详情页解决。具体字段名由实现前对照现有 schema 决定，复用已有系统，不做冗余兼容分支。
- 示例原型仅用于讨论；不得把尚未收录的评测显示成已上线数据。原型分类只是候选，不能作为逐项归类的证据。

## 详情与样例

- 优先沿用现有“测什么、具体任务、样例、评分与比较、数据与许可、版本关系、参考资料”结构；按资料内容补足具身任务所需信息。空间、设备或多模态内容丰富时可在现有样例组件中做必要扩展，不受字段顺序或固定卡片模板束缚。
- 对有真实连续记录、逐步标注或可核验时间点的任务，优先按过程展示对应视频/图像、简洁文字和目标；允许保留原始轨迹/数据入口。视频适合连续播放时不强制切成静态帧，单张图不假造过程，复杂结构化数据不删掉关键字段。
- 对仅公开任务定义的评测，显示真实任务描述、已披露的观察与目标以及官方入口，不编造图片、轨迹、成功率或参考答案。官方未公开与本站尚未整理须区分。
- 明确标识数据属性：仿真/真机、机器人形式、数据 split 和版本、素材来自人类示教/模型评测/其他来源，以及是否节选。人类示教不说成模型输出，仿真成功不说成真实机器人完成，数据生成成功率不说成模型榜单分数。
- 未核实的指标、环境和版本关系不猜测；不同试次、任务子集、机器人、seed、成功定义和协议的成绩不直接比较。原始字段和来源、许可及必要说明通过现有展开机制保留。

## 资源、版本和素材

- 每个评测详情只关联真正相关的项目资源：标注“数据集 / 仿真器 / 比赛 / 官方仓库 / 论文”等类型与官方链接。多个评测可指向同一资源；只有确有产品需求时才另设计资源页。
- 典型边界：LIBERO、LIBERO-PRO、LIBERO-Plus 不混同；RoboTwin 早期版与 2.0 分开；RoboCasa 2024 与 RoboCasa365 分开；BEHAVIOR-1K 和年度挑战规则分别注明范围。
- 对每条真实样例记录官方来源、不可变版本或 revision、数据划分、稳定 ID/行号、文件 hash、许可、下载/核验日期和允许的展示字段。视频、图像、场景素材和数据许可逐项核对；代码 MIT 不自动覆盖数据或媒体。
- 有可公开再利用授权时，在满足署名、许可、修改说明等条件下导入原始素材；未确认转载权时保留官方链接或文字说明，不抓取、热链或镜像受限素材。研究中发现 LIBERO 官方仓库与 HF 数据卡的许可标记存在不同，GraspNet 官方许可文字存在不一致，须在逐项素材确认后再决定复制；CALVIN、BEHAVIOR 与 RoboTwin 媒体权限也不能从代码许可直接推出。

## 候选清单与资料进度

- 将上一轮检索的早期到近年具身评测候选作为逐项核验范围，包含 RoboCup / Humanoid、YCB、R2R、RLBench、Meta-World、ALFRED、GraspNet、SuctionNet、RoboMimic、CALVIN、LIBERO、ManiSkill2、TOTO、SIMPLER、RoboCasa / RoboCasa365、BEHAVIOR-1K、RoboTwin 早期版 / 2.0、VLABench、EmbodiedBench、LIBERO-PRO / Plus、SIMPLE 等。赛事、数据集和仿真平台按实际性质处理，不能全归为 benchmark；若证据或本项目范围不符，标为待核或排除并说明，而非强行收录。
- 七项候选的官方资料入口和权限初核见 [官方资料研究记录](../../docs/research/2026-10-28-embodied-benchmarks-official-evidence.md)。初核不等于逐条真实样例、授权或所有版本均已验证；后续扩大搜索并保留所有未公开/未证实情况。
- 公开数据或官方页面存在不等于已拿到具体样例。实施时先取得并核验可引用的具体数据记录或媒体；实在无法取得时，详情如实展示任务说明与官方入口，不伪造站内样例。

## 实施与验收要求

1. 先核对现有工作区改动，保护已有指南和样例工作；复用既有导航、目录筛选、卡片、详情和样例组件，记录确需扩展的理由。
2. 完成领域/多任务分类、来源与样例数据模型及严格校验，核对检索、筛选、统计、目录和详情链接；已存在的非具身条目与目录行为应保持正确，避免重复实体与死链接。
3. 逐项准备官方资料、真实数据、许可/状态和版本关系；空值显示真实披露状态。完善静态路由与产物校验，包含新专区、详情页面及真实资源。
4. 严格类型检查与适当测试、正式子路径构建；在真实浏览器检查桌面/手机、深浅主题、搜索/多分类筛选、详情返回、视频图片与来源、无媒体情况和键盘操作。样例失败应有清楚状态；验证不等于真实机器人或现场环境验收。
5. 更新根目录 `UPDATE_LOG.md` 并保留无关工作区改动；提交、推送和发布另依用户的具体授权执行。
