# 具身智能专区规划地图

Label: wayfinder:map

## Destination

形成可供实施的具身智能专区方案：明确顶部入口、内容范围、分类与筛选、评测详情和真实样例展示，并与现有目录及数据模型衔接；本地图仅规划，不实施产品改动。

## Notes

- 与现有目录并列，从顶部导航进入专区；专区内可按任务筛选。
- 范围为机器人及其他物理交互评测；评测为主，数据集、模拟器和比赛单独标明类型及关联。
- 区分仿真、真实硬件、离线数据和具身问答；具体样例、来源、版本、许可必须真实可核验。
- 用户偏好中文、最简修改、复用项目现有主题与交互，代码搜索由 GPT-6 Luna 描述事实；不使用网页端 GPT。
- 前端不得重复造轮子：优先复用现有导航、主题变量、按钮、筛选、卡片、详情与样例组件；仅在具身场景确有缺口时，说明原因并做最小扩展。
- 每次处理界面设计时参考项目 ui-craft；研究以官方来源为准。

## Decisions so far

- [具身评测的官方数据与可展示样例](issues/01-evidence.md)：七项候选的任务、数据入口及许可边界已形成资料记录；具体素材仍需逐条核对。
- [具身详情页样例卡片采用什么布局](issues/07-sample-layout.md)：用户选择过程优先，以任务步骤组织样例；真实媒体需逐项核验。

- [具身专区入口与分类界面如何呈现](issues/02-prototype.md)：用户要求完全参考现有 LLM 目录，复用同一套分类、筛选和卡片样式。

- [具身评测如何分类与筛选](issues/03-taxonomy.md)：按任务多分类、单条目；专区仅按任务筛选，环境和机器人等信息放详情页。

- [具身评测详情与样例如何表达](issues/04-detail.md)：按真实数据选择展示方式，过程优先但不强行套格式；复用既有组件。
- [评测与相关资源怎样关联](issues/05-relations.md)：详情关联并标明资源类型，范围或协议不同的版本分开。

- [实施前应形成什么可核验方案](issues/06-handoff.md)：已形成可实施说明，明确候选核验与验收边界。

## Not yet specified

本次规划的决策已收口。每个候选的官方版本、具体样例及素材许可属于后续实施核验，不视作已完成事实；遇到无法呈现的复杂数据时再依据实际资料做最小设计。

## Out of scope

正式实现、迁移内容、提交发布、执行机器人评测或宣称已真机验证。
