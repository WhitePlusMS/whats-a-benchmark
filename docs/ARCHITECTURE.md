# 架构维护说明

项目使用 Vue 3、TypeScript 和 Vite SSG，保持静态内容站结构，不引入后端或全局状态框架。

## 内容与数据

`content/` 是正式内容来源。`src/content/schema.ts` 同时提供构建校验与推导类型，`scripts/content-pipeline.ts` 生成 `.generated/` 中的公开目录、样例和附件。页面只读取公开投影，不直接导入未发布的研究资料。

草稿关系沿用正式关系的结构，仅允许暂缺来源；撤回再发布不会丢失既有依据。生成器在清理旧输出前验证内容与必需的 favicon。维护命令将已完成的内容变更与附属日志故障分开报告，日志不可写时明确要求手工补记，避免误导重复操作。

目录元数据通过 `src/content/catalog.ts` 提供；样例正文按需加载，不进入首页目录包。当前保留完整目录元数据，避免为小型内容目录引入第二套详情加载和静态渲染链路。若内容规模继续增长，应依据实际传输量和加载耗时再拆分轻量索引与详情数据，不通过调高构建告警阈值掩盖体积。

`interpretation` 沿用带来源的文本结构，`src/content/interpretation.ts` 只定义详情和对比共同使用的栏目顺序、名称。可选 `composition` 描述完整综合指数，复用现有详情路由和证据组件；生成前校验权重与成员引用，删除或撤回成员时复用现有保护流程。页面不另存文案、不建立模型成绩库。工作任务入口直接导航到现有分类查询 URL。

`src/lib/search.ts` 预计算名称和全文的标准化索引；搜索及批量名称识别复用索引，保留版本号和既有排名。

## 页面、状态与交互

| 模块                              | 职责                                          |
| --------------------------------- | --------------------------------------------- |
| `src/main.ts`                     | 路由、静态生成入口与返回目录的滚动恢复        |
| `src/App.vue`                     | 站点页眉/页脚、提供应用实例状态及展示对比底栏 |
| `src/views/`                      | 页面组织及栏目展示                            |
| `src/lib/catalogQuery.ts`         | URL 查询接口、筛选/排序规则与目录统计         |
| `src/composables/catalogQuery.ts` | 将当前应用 Router 交给目录查询接口            |
| `src/lib/comparison.ts`           | 对比上限、有效 ID 去重与分享参数解析          |
| `src/composables/compare.ts`      | 对比选择与路由之间的单向状态规则              |
| `src/composables/sampleLoader.ts` | 样例请求、取消、重试、错误及过期响应保护      |
| `src/composables/sampleViewer.ts` | 当前样例、交互重置及媒体失败状态的生命周期    |
| `src/components/SampleViewer.vue` | 样例与解读的页面组织、客户端挂载门控          |
| `src/components/SampleMedia.vue`  | 媒体、附件、字幕、来源及加载失败展示          |

目录 URL 是筛选、排序、视图的唯一来源。清空筛选保留排序和视图；未知筛选值可得到空结果，不静默猜测用户意图。分类计数按完整公开目录计算，不随当前筛选变化。

对比页以 URL 的 `ids` 为准，表格与底栏读取同一份选择。移除或清空通过替换 URL 同步更新；同步连续操作合并待完成的目标选择，界面仍只读已生效的 URL，不使用串行导航队列。离开对比页后保存当前选择，供本次应用其他页面继续使用。直接打开分享链接时，挂载后恢复选择，确保静态 HTML 与首次水合一致。状态按应用实例创建，不在模块全局保存用户选择，避免静态生成时串页。

样例加载保留客户端挂载门控。切换评测、重试或卸载会取消旧请求，即使请求未能真正取消，也不接收过期结果。源数据的完整结构由构建校验负责；客户端只检查传输结果的必要结构，不引入整份内容校验库。`useSampleViewer` 统一管理当前任务：切换样例或重新加载时清除选项、答案展开和媒体失败记录，回到任务模式；任务/原始数据模式之间切换则保留状态。媒体组件接收只读失败列表、发出失败事件，不直接修改父级数组。

## 样式归属

`src/styles/main.css` 是全局样式唯一入口，按以下顺序组织：

| 文件          | 管理范围                                                |
| ------------- | ------------------------------------------------------- |
| `tokens.css`  | 主题色、正文/辅助/强调/反色文字、表面色、边框和焦点颜色 |
| `base.css`    | 元素默认值、容器、焦点、跳转正文和减少动画偏好          |
| `shared.css`  | 真正跨页面复用的按钮、标签、空态和阅读容器              |
| `layout.css`  | 页眉、页脚及对比底栏                                    |
| `catalog.css` | 目录搜索、筛选、工具栏与结果布局                        |
| `reading.css` | 发布资料、指南、关于、对比等阅读页面                    |
| `detail.css`  | 详情栏目、来源、关系及评分布局                          |

`benchmark-card.css` 由 BenchmarkCard 加载；它需要目录祖先的 `.list-view` 上下文，故使用明确类名的非 scoped 样式。`sample-viewer.css` 由 SampleViewer 以 scoped 方式加载；SampleMedia、ArcTask、PublisherMarks、EvidenceLinks 保留各自局部样式。

维护约定：

- 同一个功能的基础规则和媒体查询放在同一归属文件，不另建全局 responsive 覆盖层。
- 已有语义颜色优先使用变量；机构标识、ARC 网格及特定状态颜色保持自身含义，不把所有近似颜色强行合并。
- 状态样式使用明确状态选择器，例如 `.kind-label.evidence-state`，不依赖它恰好出现在基础类之后。
- 不因页面较长就逐栏目拆组件；有独立交互、数据生命周期或实际复用时才拆分。

## 验证与版本管理

变更后执行类型检查、相关测试和生产构建。查询测试通过生产接口和真实内存路由覆盖参数、交集、排序、连续更新及导航历史；对比测试覆盖分享、导航历史、上限和应用实例隔离；加载器测试覆盖取消、过期响应和重试；样例查看接口测试覆盖模式切换、切题、重试及媒体失败记录寿命。样式或交互变更还需要真实浏览器检查桌面/手机布局、筛选返回、对比分享以及样例答案。

源码已建立本地 Git 基线。依赖、生成目录、构建目录、本地环境文件和交付压缩包不入库；研究候选继续遵循原有忽略规则。`UPDATE_LOG.md` 记录变更原因、文件、影响与实际验证结果。未经明确要求不配置远程或推送。
