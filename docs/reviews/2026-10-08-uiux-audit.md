# UI/UX 逐页审查：说明文字、样例与链接

审查日期：2026-10-08。对象：当前工作树，含现有未提交修改和新增条目。审查依据：[Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)，本轮重新获取；焦点对比度另外参照 [W3C 非文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

## 审查范围与结论

覆盖目录、全部 92 个评测详情、对比、17 张模型发布资料卡、阅读指南、关于和 404 页面；实际打开 98 个明确路由。详情页分别在 1365×900、898×884 和 390×844 视口读取 DOM 并检查整页横向溢出；主页面覆盖 1365×900 和 390×844。18 个评测中的 27 条站内样例逐条切换检查。

页面的配色、组件风格、标题层级和主要交互已有较好的基础。最值得改进的是内容的组织：完整审计说明被大量放进摘要、样例解读和限制栏；同一出处在多个地方反复作为完整外链展示；没有内容的栏目仍占据卡片或表格行。

“相同 URL 出现多次”并非这份规范直接禁止的行为。本文将技术规范问题与阅读体验建议分别标记。保留字段对应的证据关系，同时减少显示层的重复入口，是建议的主要方向。

本文是审查结果与修改建议；业务代码和内容数据未作修改。代码搜索与资料盘点由 GPT6 LUNA 提供描述，判断由主代理结合源码、独立统计和实际页面复核。

## 详情页：具体重复在哪里

### 1. 同一资料被包装成很多完整外链

`src/components/EvidenceLinks.vue:7` 只在当前栏目内对完整 URL 去重。`src/views/DetailView.vue:339`、`:378`、`:400`、`:410` 等位置分别生成栏目依据；`:441` 起还会列完整来源索引。

| 实例 | 实际详情 DOM 外链 | 唯一地址 | 最明显的重复 |
| --- | ---: | ---: | --- |
| AA Intelligence Index | 16 | 1 | 同一 methodology 地址 16 次，分布于四个读分卡、组成、定义、任务、数据、许可、样例、评分和资料汇总 |
| Terminal-Bench 4.0 | 58 | 9 | 4.0 发布说明 17 次、GitHub release 11 次、Harbor Hub 11 次 |
| MMMLU | 33 | 8 | 官方数据卡 13 次；固定 revision CSV 在记录出处、栏目依据和底部索引中反复出现 |
| Chatbot Arena | 37 | 17 | 原始介绍 6 次；55K 数据卡 6 次；33K 数据卡 5 次；部分 URL 另带具体段落 hash |

建议：各段保留简短的“依据 [1] [2]”或一个可展开依据入口，底部完整展示来源名称、用途和域名。同一块已有数据/样例主入口时，紧邻依据区域只补充其他来源。不同的段落 hash 继续保留其定位价值。

这主要是显示方式的收拢，无需删除证据字段，也无需建立第二套来源数据库。

### 2. 主入口的名字与动作不一致

`src/views/DetailView.vue:151` 的主按钮始终为 `href="#samples"`，文字却取样例状态。例如“官方入口查看”看起来会打开外部入口，实际先在页内滚动，到样例栏后还要点击“打开官方入口”。“许可待核实”“原题限制公开”则是状态，作为主按钮缺少明确动作。

建议：站内样例用“查看真实题目”；有具体外部入口时用“前往官方样例”，并指向该真实入口；需要说明申请或限制时用“查看样例获取方式”。状态作为邻近标签保留。外链图标与实际外部跳转保持一致。

### 3. 74 页没有站内样例，标题仍为“真实样例”

`src/views/DetailView.vue:372` 无条件输出“真实样例”。非 local 分支在 `src/components/SampleViewer.vue:49` 输出状态标题、原因和外部入口；有些条目没有题目，有些综合指数本身没有独立题库。

AA 指数页面依次显示“真实样例”“官方入口查看”标签、“官方入口查看”小标题、“打开官方入口”按钮，最终仍指向同一方法页。四个元素没有增加四份信息。

建议：外部或受限状态使用“样例与获取方式”；综合指数用“组成评测的样例”，优先连接已存在的组成条目。一个状态说明、一个操作入口即可。

### 4. 空内容仍以完整卡片展示

`src/views/DetailView.vue:301` 固定渲染 4 个数据画像卡片，`:306` 对每个空数组重复输出“本站尚未整理此项，请查阅官方资料。”。AA 指数、AA-Briefcase、AA-LCR 等各出现 3 次；内部前端偏好条目出现 4 次。

建议：有内容的项按需渲染；如果关键信息尚未确认，在整节保留一次说明，注明具体缺项。对没有独立数据集的综合指数，不用未知 split、字段、文件三张空卡去套数据集模板。

### 5. 核验记录与读者需要的限制混在一起

`src/views/DetailView.vue:408` 将所有 limitations 原文当作“适用范围与限制”展示。MMMLU 的限制包含固定 revision、40 位提交标识、0-based 行号、SHA-256、本轮只查首行、未逐项审核权利链等。

同一页的“数据概况”“规模”“复用许可”“本站解读”“适用限制”又多次提醒样例核验与测试污染。Terminal-Bench 4.0 的访问要求和限制都写到本轮未下载完整任务包。

核验记录有保留价值，但其作用是描述本站处理资料的范围。读者想理解的是：题目做什么、怎样算分、成绩能否比较、是否能看到样例。

建议：正文保留会影响解释成绩的限制；来源版本、行号、哈希、下载范围和本轮处理过程集中到“资料核验记录”折叠块。样例旁的许可保留在现有“记录与许可”中；重要的限制以短句说明。

### 6. “如何读分”与“评分方法”有职责交叉

`src/views/DetailView.vue:200` 的四个读分栏目在正文最前；`:384` 的指标、方法和限制在样例之后。11 个补充读分的条目拥有两处有关评分的区域，81 个原条目只有后面的评分区，阅读顺序也因此不同。

建议：将“指标是什么、谁判分、怎么算、比较要核对什么”组织为一个评分主区域；版本变化进入版本关系；数据是否公开和复用要求进入数据/许可区域。目录导航可保持少量明确的栏目。

可以采用的阅读顺序：一句话用途 → 具体任务 → 样例/获取方式 → 评分与比较条件 → 数据与许可 → 版本关系 → 官方资料及核验记录。

## 目录卡片与文字

`src/components/BenchmarkCard.vue:31` 直接复用 `officialDefinition.summary`，详情顶部 `src/views/DetailView.vue:149` 和对比第一行 `src/views/CompareView.vue:23` 也使用该字段。

同一摘要在列表、详情和对比出现是合理复用。问题在于摘要已承担完整的任务定义、版本历史、审计边界和纠正误解。

最长五个摘要为 SWE-bench Verified 210、SWE-bench Pro 198、SciCode 191、WANDR 173、Terminal-Bench 4.0 153 个字符。宽屏首行被 Verified 的长说明拉高，MMMLU 和 AA 指数卡出现明显空白；手机目录整页约 34,995px。

建议给摘要设定编辑规则：一句话说明任务，再加一项最关键的区分点。40–80 个中文字符可作为本站的编辑目标，这是本次建议，不是规范中的强制长度。版本修订、计数冲突、核验步骤放在详情的对应位置。

Verified 的候选摘要可为：“给出真实 GitHub issue 和代码仓库，要求智能体提交补丁并通过测试；Verified 是人工筛选的 500 项子集。”其余筛选条件继续保留在详情。先修改文案，再决定是否需要视觉截断。

中文栏目建议采用读者能立即理解的表达：官方定义 → 测什么；任务协议 → 具体任务；预期输出 → 需要完成什么；执行环境 → 使用哪些工具与条件；复用与许可 → 能否使用这些数据。准确的术语可继续出现在详细说明中。

## 样例阅读器

`src/components/SampleViewer.vue:75` 的模式按钮使用 aria-pressed；原生 select 有名称；参考答案默认收起；记录与许可使用原生 details。加载状态有 role=status，失败有 role=alert 和“重新加载”。这些应保留。

27 条记录逐条切换，未发现媒体错误提示或整页横向溢出。MMMLU 的键盘参考答案展开和原始数据切换正常，原始模式明确提示包含答案。未执行真实评测，也未据此验证参考答案的学科正确性。

值得修改的是“本站解读”的重点。目前 MMMLU 的解读强调“官方 CSV 原文一致”“污染风险”“不是禁止转载”，在许可和限制栏还能再次看到。建议以任务解释为主，例如：“题目要求判断代数扩张的次数，并从 4 个选项中选择答案。它展示 MMMLU 如何以不同语言呈现学科题。”来源与许可沿用现有折叠记录。

## 对比页

`src/views/CompareView.vue:96` 固定生成四个 interpretation 行，`:106` 对空值逐格输出同一占位句。MMMLU 与 MMLU 对比时，4 行、2 列都没有数据，共 8 次占位；整个表包含 19 行，其中 1 行为表头。

建议：所有对比项都没有该字段时不渲染此行；只有一列缺项时用简短缺值标记，统一解释一次。92 条中 81 条尚无 interpretation，这能改善大量常见组合。

`src/styles/reading.css:63` 的表格支持局部滚动；手机实测容器 333px、表格 720px，右方向键可滚动 40px。表头和首列没有 sticky，向右会失去维度名称。建议固定维度列；需要保留列名时再固定表头。此项属于阅读体验建议。

`src/views/CompareView.vue:88` 的参考资料只取 sources[0]，按钮均为“查看来源”。建议显示来源名称，或提供“查看该评测的全部资料”的详情锚点。
