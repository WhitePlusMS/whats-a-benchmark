# 评测界面设计与验收标准

读者从目录找到一项评测，打开真实案例，理解输入、交付物与判分，再去评分说明或原始来源核对。模型和具身评测共用组件与交互规则，任务内容决定使用文字、图解还是媒体。

## 页面与组件

| 页面 | 共用规则 |
| --- | --- |
| 模型和具身目录 | 列表和卡片共用 `BenchmarkCard.vue`。标题进入详情，案例入口使用与详情相同的动作文案。按钮写清评测项数，目录统计注明案例条数。手机首屏优先搜索、筛选和第一张卡的案例动作。 |
| 评测详情 | `BenchmarkDetailHeader.vue` 复用 RoboQuest 首屏骨架。各条目提供自己的任务说明和评测标识，入口直达案例及评分。案例锚点附近显示评测名和评分快捷入口。 |
| 真实案例及入门 | `SampleViewer.vue` 负责选题、展示模式、答案、加载状态和来源。一个样例区只展示一张当前案例卡。短题名用于选择器，完整题名用于正文。 |
| 样例获取 | 用真实案例、任务示例、组成样例或获取方式标明目的。申请与许可说明放在外链前。指数的真实记录标明提供记录的组成项。 |
| 对比 | 宽屏目录用浮栏确认选项，手机目录在结果上方确认，结果页内管理选择。刷新目录恢复本标签页选择，分享链接恢复对比项。宽屏使用表格，窄屏优先展示输入、交付、评分、版本和关键限制，每个维度列出全部已选评测。两端使用相同的内容和来源链接。 |
| 参考资料及发布资料 | 引用编号指向紧凑的来源索引。标题写可识别的对象、文件或定位，类型、域名、核验日期另作元信息。发布资料卡显示标题、发布方、发布日期和官方入口。 |

## 案例卡结构

1. 选题控件和展示模式固定为「任务内容」「原始数据」。公开答案及原文节选的说明放在对应内容附近。
2. 题名下首先给出任务摘要。结构化导读依次展示输入、交付和验收。说明对应真实任务，保留材料或附件的边界。
3. 真实媒体、网格和步骤图在同一卡内按任务需要展示。RoboQuest 用视频、观测与结果，Terminal-Bench 4.0 用步骤图，Aider 用文字与原题。图解明确标注来源或本站整理。
4. 长节选与原文在任务说明后按需展开，来源和许可始终可以查到。正式评测、示范和站内练习分别标明用途。
5. 选择题默认收起参考答案和相关解读。切题或刷新回到待作答状态。原始数据入口提前提示可能包含答案；分享链接恢复对应样例和阅读模式。
6. 统一处理加载、失败重试、无记录和未知样例。媒体重试保留当前题目、阅读模式和答题状态。

## 视觉与响应式

- 共用字号、间距、卡片及控件圆角和触控尺寸在 `src/styles/tokens.css`。正文基础字号 14px，辅助信息 12px，手机主要控件触控高度至少 44px。
- 同类卡片共用间距、边框、操作位置和按钮状态。视频、网格和代码块只在自身需要时局部滚动。
- 交互沿用共享焦点样式。切换动画帮助理解步骤，支持 `prefers-reduced-motion`。深浅主题分别检查。

## 执行与验收

- 修改共用规则时，优先改共用组件和样式，再检查所有相关模板。单项改造按 benchmark 单独提交，已有改动逐文件核对。
- 核对实际使用的版本、样例、原始来源与许可。可核验材料不足时，在获取区写清缺口并提供官方链接。
- 类型检查、内容校验、测试与构建均通过后，在桌面、390px 窄屏、放大重排和深浅主题下检查。用键盘完成选题、揭示、评分跳转与对比。覆盖样例加载失败、媒体重试、无结果、未知样例和对比数量边界。
- 用 Aider 检查文字和引用，SWE-bench 检查图解及验收顺序，RoboQuest 检查媒体，CMMLU 检查答案揭示，HLE 和指数检查获取说明及组成项。记录自动覆盖、浏览器检查和待人工确认的范围。
