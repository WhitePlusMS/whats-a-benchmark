# RoboWM-Bench：从生成视频到仿真执行，以及复现者的问题

调查日期：2026-11-10。本记录依据论文 v2、固定版本仓库、公开问题和已有中文说明；没有执行生成、动作提取或机器人任务，也没有重标视频或采访读者。不同机构的成绩、日志和问题不属于同一次实验。

## 和本站已有评测是什么关系

[RoboWM-Bench 论文 v2](https://arxiv.org/html/2604.19092v2)以初始图像和任务说明生成未来操作视频，再把机器人画面转换为关节动作，或把人手画面进行姿态跟踪和动作重定向，最后在 LeHome 仿真环境检查关键步骤及任务结果。论文的任务级成功要求所有关键节点通过且最终目标完成；人工设定的判据及视频转动作接口也会影响结果。最终执行发生在仿真中，不是直接把模型生成的视频控制真实机械臂得到的成绩。

这和本站 [EmbodiedX](../../content/benchmarks/embodiedx.json) 都涉及世界模型，但 EmbodiedX 特定赛道重点是满足质量门槛下的硬件推理效率；它的 DROID 输入片段也不是 RoboWM 任务运行。本站 [SIMPLER](../../content/benchmarks/simpler.json) 的单次仿真策略视频是机器人策略执行案例，而 RoboWM 评估的是世界模型生成的视频能否经转换后通过仿真检查。名称、输入和来源相似不使数字可直接合并。

本轮按本地 `content/benchmarks` JSON 的顶层 ID、name、subtitle、aliases 搜索 RoboWM 和论文编号，未发现独立同名条目；这不是对所有正文的语义搜索，亦不等于全网无人介绍。本轮不新增产品条目。

## 看似相同的百分比衡量不同环节

- 论文表 1 的机器人关抽屉任务：原始 Cosmos 为 0%，Cosmos-FT 为 90%。作者称后者每任务用 50 条真实操作轨迹微调；这是特定生成及仿真协议中的论文报告，不是同等训练数据的零样本排名，也不是现场成功率。
- 论文表 2 处理真实成功轨迹的视频并在重建仿真中回放动作。机器人视频的纯真机数据训练 IDM 平均 71.4%，仿真预训练加同样真机数据微调的 IDM 平均 95.7%，分别是七项任务的表内平均。两个数检验动作提取与回放，不能当世界模型的生成视频成功率。
- 论文图 5 列七项机器人任务各 10 条真实成功、10 条真实失败轨迹；作者报告直接在仿真回放相同低层动作后，各任务的两类结果都为 10/10 一致。这是特定筛选轨迹和场景的作者实验，不经过视频转动作，也不保证其他物件或工况的仿真保真。本次未查看原始轨迹。

论文还声明人手视频是重定向为机器人动作而非直接模拟人手动力学，关键步骤检查器按任务人工指定；接触和边界状态尤其可能受到接口误差影响。每一层均需标注，不能把整个链路失败一概归因于视频生成模型。

## 具体复现问题与已有回复

论文写每任务有 10 个共享的初始物体配置。[复现者 issue #7](https://github.com/fffstrong/RoboWM-Bench/issues/7)询问为何公开关抽屉和按按钮输入图片分别只有 3、5 张，也请求模型大小、分辨率和完整配置。固定提交 [`0a8b0eab`](https://github.com/fffstrong/RoboWM-Bench/tree/0a8b0eab3ebfb7993f6ab895f12eac41dfefa1c1/wm_inputs) 的 GitHub 文件树本次确有对应 3、5 个 PNG；另有每张的文字文件和补充提示词文件。文件数量不一定与仿真初始状态数量一一对应，尚未获得论文每次运行的完整对应表，不能断言实际只使用这些状态。

维护者在 issue 中称两个任务对单张图重复试验、调整过提示词，并补充提示词；还列出 Cosmos 2B 的输入尺寸、输出帧数等参数，表示修改过部分生成代码以处理配置不生效。提问者在 2026-07-07 仍请求完整提示词。这里的代码修改只是维护者描述，不足以确定复现差异根因；其提供的说明也不应当被称为本站独有。

另一位复现者在 [issue #8](https://github.com/fffstrong/RoboWM-Bench/issues/8)自报八个人手任务的 Cosmos 结果约为 0%，而论文表 1 中不同任务并非全部为 0%。他报告检测到手部却观察到重定向后的动作较小，并提出深度估计等可能原因；页面当次未见作者回复，本次没有其生成视频及完整配置的独立验证。不能把他的推测当成已确认缺陷，也不能推断论文结果错误或所有模型有此问题。

[issue #2](https://github.com/fffstrong/RoboWM-Bench/issues/2)另有一位使用者报告旧提交中 reset 接口不匹配及自改后的 7/10 回放；维护者称已上传接口修改并建议调整成功检查频率，使用者致谢。这个关闭的历史问题不能直接当作当前固定提交仍存在的错误，也不能与 issue #8 的症状归为同一根因。

## 已有说明和使用边界

已有 [中文研究介绍](https://www.gairdao.com/app/articles/on9mxv9t)讲解了生成视频、动作转换和仿真执行；[WAMs 研究报告](https://rcl-robotics.github.io/Awesome-World-Action-Models/reports/2604.19092/)也逐项关联论文证据与微调条件。因此中文说明、任务拆解和成绩出处并非空白，本站是否更易查找必须比较验证。

官方 [固定版本 README](https://github.com/fffstrong/RoboWM-Bench/blob/0a8b0eab3ebfb7993f6ab895f12eac41dfefa1c1/README.md)提供仿真、动作转换、输入及评估步骤和权重链接。访问时 GitHub API 未识别根目录许可证，文件树中也未发现根目录 LICENSE；不据此判断每项子模块、素材或权重许可，也不把公开代码视为全部数据均可转载。未安装或验收 README 的命令。

对现有项目，可测试读者能否分清“模型生成视频的仿真执行分数”“转换器回放分数”“真实动作在仿真的一致性”三种数字，再与论文、已有中文介绍比较；复现提问证明有人需要对应配置，不证明其需要本站、会持续使用或愿意付费。
