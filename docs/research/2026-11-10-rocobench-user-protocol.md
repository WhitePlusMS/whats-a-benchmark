# RoCoBench：多机器人任务、复现反馈与衍生协议

核查时间：2026-11-10。对照原论文、项目公开 issue、后续论文和本站现有具身条目；未执行模拟、访问模型 API 或联系用户。

## 原版任务与分数

[RoCo 论文](https://arxiv.org/html/2307.04738)的 RoCoBench 是六项桌面多机器人协作任务，并区分并行/顺序任务、共享/不对称观察和工作区重叠。`Pack Grocery` 是两台机器人从桌面取放物品到容器，任务要求路径协调；论文给出的可用动作包含取放、目标和空间路径。论文表 2 还同时记录有限回合内的任务成功率、成功回合的环境步数和所有运行中的平均重规划次数；这些不是同一个指标。

例如论文表 2 的 `Dialog` 行给 `Pack Grocery` 成功率 `0.44 ± 0.06`，并在表注写明每任务 20 次运行。它属于论文指定模型、提示和反馈设置下的仿真实验；不能直接与任意代码版本、预算或实机演示混排，也不把 `±` 自行解释为某种置信区间或据此推算分母。

## 可核查的使用者问题

- [issue #8](https://github.com/MandiZhao/robot-collab/issues/8)：一位中文使用者称用 GPT-4 跑打包任务时，前两个步骤完成，后续不断出现碰撞，重新规划产生 API 费用；页面查看时无回复。这是其个人运行报告，不能据此确认原因或推广到所有运行。
- [issue #12](https://github.com/MandiZhao/robot-collab/issues/12)：另一位使用者称大部分实验接近论文数据，但打包任务未完成，日志多次显示 `ReasonCollisionAtStart_time0_iter0`；2025 年一位评论者询问是否已解决，未见作者诊断。即使症状类似，也不能证明与 #8 是同一故障，更不能将他有限次数的失败当成原论文成绩的纠正。
- [issue #7](https://github.com/MandiZhao/robot-collab/issues/7)：一位使用者报告打包和柜体任务的渲染物体缺失，并称自行取消 XML 中相关 mesh 注释后看到异常物理表现；另一人表示遇到类似问题。没有独立运行或维护者结论，不能断定问题根因或影响了论文实验。
- [issue #13](https://github.com/MandiZhao/robot-collab/issues/13)：用户称载入看似相同的状态、给同样计划时抓绳有时失败。未核实其完整随机状态、依赖与环境，也不能据此断言模拟器非确定性是原因。
- 另一个项目的 [OpenGVL #34](https://github.com/budzianowski/opengvl/issues/34)询问 LeRobot/数据格式兼容版本，用户怀疑加载问题与格式有关；这是用户假设，非已确认根因，也不是 RoCoBench 问题。

这些问题真实存在于公开讨论，支持有部分开发者需要更易找到运行条件和排错线索；没有证据表明发帖者希望使用本站，也不能把五个 issue 当成五份有代表性的市场访谈。页面与回应可能变化。

## 其他人已做什么，为什么不能直接混榜

后续 [ReAd 论文](https://arxiv.org/html/2405.14314)提出 `DV-RoCoBench`，选择扫地、做三明治和分拣方块三项，加不同难度。作者称原版有技术问题，因而选取其能运行的任务；未说明本次查到的上述具体 issue 与该论文选题是否同因。论文的条件还包括每回合最多 15 个环境步骤，以及每步不同的重规划上限。它不是原版六任务全部结果，不能只按共同任务名与原论文总分混在一起。

原论文附录已公开机器人能力、观察和任务定义，[原项目仓库](https://github.com/MandiZhao/robot-collab)也给出环境搭建及运行入口，BenchNavigator 有概览；“任务介绍”并非空白。与本站已有的 [RoboTwin 2.0](../../content/benchmarks/robotwin-2.json)双臂传递案例相关的是协作主题，但不是相同模拟器、机器人、任务或测量协议。

## 对产品判断的含义

可验证的具体方向是让开发者在读某个失败结果时，快速区分模型规划、碰撞反馈、环境资源和调用预算，并连到原始问题与回应；这是对这些材料的归纳，不是已经实现的诊断功能。原始 issue 和论文已有这些信息，仍需与直接搜索、项目文档做用户对照，确认本站是否真正节省时间。不能承诺给出具体故障的修复建议或代替维护者判断。
