# LIBERO-Plus：复现疑问、输入指令与现有资料

后续分类核查：[任务组与扰动数量对照](2026-11-09-libero-plus-task-count-reproduction.md)直接复算固定版本分类文件，确认其部分分组数量与论文表 7 不同；差异原因和分数影响尚未确认。

## 本站条目与用户关心的问题

[本站 LIBERO-Plus](../../content/benchmarks/libero-plus.json)介绍原 LIBERO 的七维扰动和按条件成功率；记录的两条样例分别是第三方 π0.5 的一次背景纹理扰动仿真冒烟测试，以及官方链接的训练集单条轨迹，且已在解释中区分两者。冒烟测试不等同官方完整榜分数或真实机器人表现；未核对第三方当时使用的完整环境代码与实际提示词，不能推断该单次样例被下文问题影响。

[官方 README 固定提交 `4976dc3`](https://github.com/sylvestf/LIBERO-plus/blob/4976dc30028e805ff8094b55501d532c48fec182/README.md)写有 10,030 个扰动任务、七个维度，并要求将每个任务的试验次数从原版的 50 调整为 1；维度分类和难度需按官方映射查。这是该版本公开协议，不意味着 10,030 个相互独立的原始任务，也不能把单条成功样例当作该模型的总体成功率。

## 同一个榜单：分数和复现记录有具体冲突

官方固定版本榜单列 π0 的 Sensor Noise 成绩为 **79.0%**。在 [LIBERO-Plus issue #61](https://github.com/sylvestf/LIBERO-plus/issues/61) 中，报告者称使用 OpenPI 的 `pi0_libero` 检查点及全部 10,030 个任务，在两档重规划间隔下分别得到 **16.4% 和 17.6%**；评论中另有使用者自报相似低分。讨论要求提供原榜检查点、版本、摄像头噪声处理、提示和原始记录；本轮读取时 issue 仍开放，未见维护者解释完整原因。

同帖引用的[另一篇论文表 3](https://arxiv.org/html/2605.02757)确有 π0 在 Spatial 子集的 19.9%，但那篇论文使用自行微调的检查点和**Spatial 子集**，与完整榜单不是同一次评测，不能简单拼成同一组受控重复试验。多个自报出现差异值得核查，尚不能据此说官方 79.0% 一定错误、把低分作为标准值或断言根因为某一配置。

[VLA-JEPA issue #19](https://github.com/ginwind/VLA-JEPA/issues/19)是另一个模型的复现报告：提问者及另一评论者分别描述训练后结果与公布结果不同，维护者询问训练阶段、batch 与步数，并表示会调查；第二位评论者也明确改过一次训练实现。本次没有查到最终排查结论，不能将其归到上述 π0 榜单争议或假设训练改动无影响。

## 输入指令中的扰动标记：源码、报告与修复状态

[固定提交源码 `benchmark/__init__.py`](https://github.com/sylvestf/LIBERO-plus/blob/4976dc30028e805ff8094b55501d532c48fec182/libero/libero/benchmark/__init__.py#L43-L69)的 `grab_language_from_filename` 对不含 `_language_` 的名称按下划线拆分得到语言字符串；同文件将结果写进 `Task.language`。因此，名称中含有的扰动后缀会留在该字段中；**是否最终传给模型仍取决于具体评测调用方**，不能仅据这一源码断言全部历史成绩的真实输入。

[issue #64](https://github.com/sylvestf/LIBERO-plus/issues/64)的报告者指出，某些评测管线使用了该字段作为模型提示，并给出例子；[issue #65](https://github.com/sylvestf/LIBERO-plus/issues/65)另一报告者声称在指定版本、`pi05_libero`、Object suite 的 396 个相机扰动任务上配对比较：使用名称派生提示时 333/396（84.09%），使用其从基础 BDDL 读取的提示时 365/396（92.17%）。报告者称仅计划改变提示，记录了 43 个仅后者成功、11 个仅前者成功；本站未运行或审计控制变量和数据。两种提示方式属于不同的评测设置，不能默认其中一个可直接替代原榜。

[PR #71](https://github.com/sylvestf/LIBERO-plus/pull/71)提出从 BDDL 读取 `task.language`，当次页面显示 **Open，未合并**。另一个 [PR #74](https://github.com/sylvestf/LIBERO-plus/pull/74)针对四个 BDDL 文件中另行报告的指令内容异常，也显示 Open；这两项并非同一问题，不能将“改用 BDDL”自动视为所有输入都已正确。PR 作者的测试结果及修复有效性本次未复验。

这些证据支持在**特定版本、具体调用链和具体样本**下关注提示词，但不证明它造成 #61 中 π0 的全部噪声分差，也不证明所有模型、历史版本或本站样例都受影响。读取 BDDL、基准维护和成绩更新均需具体场景再确认；本轮不改站内评测数据。

## 原始 LIBERO：仿真器版本的复现反馈

[OpenVLA issue #282](https://github.com/openvla/openvla/issues/282)中，一位使用者称按官方脚本与发布检查点评测，LIBERO-Object 为 68%，而其引用的论文结果是 88.4%；他记录了修改种子、步数和关闭 flash-attention 等尝试。另有使用者报告类似差异。后续有人指向 [LIBERO issue #88](https://github.com/Lifelong-Robot-Learning/LIBERO/issues/88)，该帖作者报告 MuJoCo 3.3.3 的图像渲染与原始数据不同，回退到 3.3.2 后画面恢复。OpenVLA 提问者随后自报使用 3.3.2 得到 85.2%，并关闭其 issue；另一评论者也自报结果回升。

这些是公开讨论中的运行报告，不是本站复验；原始配置、完整逐次试验和其他潜在差异未独立审计，不能将分差全部确定归因于渲染版本，也不能把该解决方式推广为所有环境的通用修复。这里讨论的是原始 LIBERO-Object 仿真，不是前文 LIBERO-Plus 某次扰动或真机表现。它提供一个用户确实遇到的版本排查案例，也已有社区帖子直接提供线索。

此外，[一份 SmolVLA 复现笔记](https://huggingface.co/blog/zuoxingdong/smolvla-libero-spatial-eval)已整理此渲染问题及多个其他 issue，作者把 3.3.2 作为其特定实验的参考版本；[OpenWAM 的 LIBERO 指南](https://github.com/OpenWAM-Official/OpenWAM/blob/main/benchmarks/libero/README.md)也说明在其环境固定并检查该版本。两者是现有可用线索，不代表所有方法都应使用同一版本；本站未运行或验收这些教程。把排查记录关联基准的形式并非本站独有。

## 相机安装漂移：仿真分数、真实设备和已有排查工具

- [LeRobot issue #4496](https://github.com/huggingface/lerobot/issues/4496)的报告者称，在 SO-101 的一次两分钟采集中，两个固定背景参照点的图像坐标发生变化；他认为外置三脚架相机发生漂移，但现场没有发现。他后续尝试从该数据集恢复原视角未成功。报告中的像素变化不是相机移动的毫米数，本站未拿到原视频或复现，不能断定它造成了具体策略失败或所有采集都会漂移。
- 同一报告者提出保存相机参考帧及机械臂姿态，并提交 [PR #4495](https://github.com/huggingface/lerobot/pull/4495)；2026-11-09 读取时 PR 为 **Open**，不是已合并的官方功能。他也解释腕部相机随机械臂移动，比较两帧之前需控制机械臂姿态；该方案作者自行报告测试结果及局限，本次未运行。另一评论者称其关注 SO-101 训练中的类似问题并询问是否出现在其他会话；这不构成独立复现实验。
- [WARP-VLA 论文](https://arxiv.org/html/2610.11508)对 LIBERO 仿真手腕相机扰动，报告 π0.5 在小、中、大扰动上的平均成功率 **39.2%**，增加作者方法后为 **78.3%**；平均不含标准安装。该适配器以 2,000 条 LIBERO 示范及重渲染训练，不是无需训练、无代价的性能提升。它对 LIBERO-Plus 的评估也额外施加手腕相机变化，不能直接当作原项目某个现有榜单条目。
- 同论文的真机实验使用 xArm6、夹爪、两个外置与一个腕部相机、10 个任务；每个任务和相机配置测试 5 次。作者报告 π0.5 标准安装 **78%**、九种腕部扰动配置平均 **36.7%**，加入 WARP 方法后分别为 **80%** 和 **48.7%**。作者用标准安装的每任务 50 条真机遥操作示范微调基线，并用其图像计算锚点；仿真训练的适配器保持固定。两组数来自特定实验与平均口径，不应与单任务 5 次试验、本站单次视频或其他硬件直接合并，也不保证现场表现。本次没有重跑。
- 相机**安装位置**与相机**输入键映射**是不同问题。[LeRobot 官方教程](https://huggingface.co/docs/lerobot/en/il_robots)说明训练和部署应对齐相机名称、分辨率，并给出重命名入口；[Viam 的 VLA 服务仓库](https://github.com/viam-labs/vla-inference-service)描述离线将预测动作与数据记录对照，并允许显式指定相机键映射。其开环误差不能保证闭环任务成功，也不能单凭这一指标断定错误根因；本次未安装工具或测量机器人。

本站样例中的 π0.5 单次录像属于**背景纹理扰动**，不是论文的腕部相机实验，不能据此推断本站样例受相机漂移影响。这些资料显示机器人部署和可靠评测存在实际工作，但现有教程、研究和工具已覆盖一部分；是否需要本站做跨来源导航、能否节省时间仍未做读者验证。
