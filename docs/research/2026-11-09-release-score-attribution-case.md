## 具体案例：同一模型卡中的对象与设置

[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)标题是 `Qwen3.8-2.4T-A95B`，但其成绩表的列标题是 `Qwen3.8-Max`。卡片称 Max 基于该权重版本，提供额外的视觉输入、非思考模式、默认上下文和工具等功能。成绩表中 Terminal Bench 2.1 的 Max 一列为 **86.6**；脚注称其使用 Claude Code、avg@10、5 小时超时、131,072 max tokens；其他模型的同表比较值则选择不同框架的已发表结果。

因此一条忠实摘录至少要保存表列对象、原始分数、具体测试名与版本、框架、重复次数、来源和已披露限制。**不能仅因为页面 URL 是权重仓库，就断言这个数是以该仓库原始 checkpoint 独立复测的结果。** 同样，仅凭卡片不能判定具体运行所用服务内部实现，未披露的内容应留空，而不是猜测。

[Hugging Face 上的成绩录入提案 #38](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B/discussions/38/files)也把 86.6 写入该权重仓库的拟议 YAML，并在 notes 中明确写该成绩以 Max 产品名报告，未必等同单独的开放 checkpoint，保留 Claude Code 和预算信息。其[讨论页](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B/discussions/38)显示 ready to merge；本次不能把该提案当作已合并的主分支数据、Qwen 团队对具体运行的进一步确认或独立复测。提案还提供日期，但卡片本身未在对应成绩处清楚说明真实运行日期，不能自动把提案日期当实测时间。

这个案例与本站 [Terminal-Bench 2.1 资料研究](benchmarks/terminal-bench-2-1.md)及[此前 Qwen 发布来源核查](2026-09-23-china-releases-stepfun-qwen.md)相连；已有本地条目记录发布与评测资料，并没有模型成绩数据库。这里补充具体数值和待合并录入的证据，不说明本站或提案作者已经测出模型成绩。

## 已有直接竞品：Benchmark Radar

[Benchmark Radar 页面](https://benchmark-radar.org/)有 benchmark 搜索、模型矩阵、趋势和榜单相关入口；页面称点击模型成绩可以查看设置和来源。本次通过网页正文确认这些界面与说明，未完成动态交互或逐条核验成绩。

项目方[论文](https://arxiv.org/html/2609.11115)描述其目录汇集模型报告、LLM Stats、Artificial Analysis 和 OpenCompass，并将不同来源的同名条目保留为独立记录。它报告的 v0.11.0 截止快照有 1,283 条**来源记录**、12,916 条数值观察；不能把它们分别等同于独立 benchmark 数或独立测试次数。论文还区分了模型发布日期、文档日期与实际评测日期，这些日期不能自动互换。其项目所声称的采集、设置完整性和现有在线数据，本次未逐项实证。

这与“评测资料 + 模型发布材料 + 成绩来源和设置”的方向直接重叠；它不能证明本项目没有生存空间，但也不支持宣称这一组织方式是空白。其开源 README 的来源描述见[项目仓库](https://github.com/ktwu01/benchmark-radar/blob/main/README.md)。

## 发布材料能覆盖多少：一项有限范围的研究

[Benchmarking-Cultures-25 论文](https://arxiv.org/html/2605.14164)人工检查 11 家组织的 139 个 2025 年模型发布，112 个发布明确突出至少一项 benchmark；研究者报告，样本中 63.2% 的被突出评测仅由一家所选厂商使用，38.5% 仅在一次发布中出现。其范围是筛选后的厂商面向公众的首发公告，不涵盖所有模型、模型卡和所有评测；作者还对名称及版本做规范化。不能把比例直接外推为当前项目数据库必然有同样程度的缺失或不可比。

研究的数据集位于 [Hugging Face](https://huggingface.co/datasets/matybohacek/benchmarking-cultures-25)，其交互站在本次访问时返回 403，无法验证当前交互或数据状态。论文研究发布中提及什么，不等于为每个模型提供一套统一可比的逐项评测。

## 对产品决策的意义

厂商公布的分数有价值，能回答“厂商在什么材料里声称了什么”；但一个结果应以**具体版本、执行与报告方、任务版本、框架、汇总方式和日期依据**一起阅读。不同条件可以并列展示，是否足以得出排序要看原始披露，不要把未知补齐。

针对这个案例，可邀请有模型选型或复现任务的读者分别使用官方模型卡、Benchmark Radar 和一张候选说明卡回答：86.6 的表列对象是什么？测试框架是什么？是否已证明开源 checkpoint 的独立成绩？记录完成时间和错误，不直接默认候选卡更好。目前尚无此实验结果。
