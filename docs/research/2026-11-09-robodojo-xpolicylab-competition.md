# RoboDojo 与 XPolicyLab：跨评测入口和复现条件

调查日期：2026-11-09。基于本地条目、固定提交的公开文档、论文和已有使用问题；未运行仿真、实机、适配器或第三方代码，未采访用户。状态为当次快照，站点和仓库可能变化。

## 用户能从本站已有条目得到什么

本地 [RoboDojo](../../content/benchmarks/robodojo.json)描述仿真和实机分别阅读，并有两个可区分的案例：官方仿真演示 `sweep_blocks` 与第三方 `align_blocks` 评测日志。后者在标准 200 步截点未成功，延长到 335 步记录成功；条目明确两段来自**同一轨迹**，不应视作两次独立试验或把延长预算直接混入标准榜。样例不是本站实测的整体模型成绩。

本地还收录 [RoboTwin 2.0](../../content/benchmarks/robotwin-2.json)，与 RoboDojo 都涉及双臂任务，但不是同一个任务集和评分体系。RMBench 基于 RoboTwin 研究任务记忆；此前已在[机器人记忆专项](2026-11-09-robot-memory-benchmark-crosswalk.md)讨论相近问题。本站 `RoboDojo` 条目的 `related` 目前为空；这只是当前字段观察，不代表没有其他导航或正文链接，也不单凭它断言读者找不到这些关系。

## 直接替代品：跨基准接口、文档和榜单

[XPolicyLab 中文 README 固定提交 `6baccd5`](https://github.com/XPolicyLab/XPolicyLab/blob/6baccd57ff958570d0db1588370289ee36c8bb70/README_zh.md)描述以策略适配器和环境客户端衔接 RoboDojo、RoboTwin 及 RMBench，并指向各自榜单；它提供中文入口、模型专用说明和调试流程。该提交自报 2026 年 11 月接入 77 个策略，另一页面或论文可能报告不同时间的数量；本轮未清点目录、安装或验证每个模型可运行。

[RoboDojo 官方提交说明](https://robodojo-benchmark.com/doc/usage/robodojo-submission/)要求先提交适配器 PR，再提供代码提交、检查点、任务、机器人配置及动作空间；页面称评测团队运行所需测试并审查复现材料后，可依规则上榜。这里是对方**发布流程的说明**，不是本站审核每一历史榜单条目均经过相同处理，也不是远程真机服务可用性的验收。

[RoboTwin 官方 XPolicyLab 文档](https://robotwin-platform.github.io/doc/usage/xpolicylab.html)也说明通用参数、模型侧服务、环境客户端、输入解码及调试。其 debug 示例只检验接线，不能当作仿真或真实机器人成功率。共享接口有助于接入，不保证不同评测的任务、控制、训练数据和结果可直接合并。

[XPolicyLab 论文 v3](https://arxiv.org/html/2608.09892v3)还报告 6 名工程师完成 π0.5 到 RoboDojo 仿真的同一接入任务，三种条件按不同顺序进行：从零约超过 5 小时、手动使用框架约 2 小时、配合 agent skills 约 30 分钟，中位数不含权重下载。论文作者明确提醒参与者会逐渐熟悉模型；这是一个任务的小样本接入研究，不是所有模型、团队和部署场景都能达到的节省时间，也不是对本站产品的需求验证。项目作者提供框架，存在方法利益关联。

## 同一个模型：成绩接近不等于完整复现

[RoboDojo 论文表格](https://arxiv.org/html/2607.04434)报告 π0.5 在 Memory 维度的综合得分 / 成功率为 **5.78 / 4.56%**；前者包含部分进度，后者是二元成功率，不能看作两个同义百分比。

[第三方复现文件固定提交 `76dc4d7`](https://github.com/worv-ai/vla-evaluation-harness-public/blob/76dc4d7c03677bd4be58e97b85b6726690c573a8/docs/reproductions/robodojo.md)把其 π0.5 Memory 得分 / 成功率写为 **6.4 / 5.6%**，看起来接近原论文；但该记录同时说明：

1. 实际只完成六个 Memory 任务中的四个，每项 15 次；使用一个训练 seed。其引用的原协议是每任务 50 次，论文参考为三个训练 seed 均值。
2. `press_by_number` 和 `swap_blocks` 因其当时的适配器复位问题没有产生有效 episode，第三方在这个展示均值中将两项按零计入；不应把“没有结果”视为模型已测试且成功率为零。
3. 作者称后续修正了适配器生命周期并做部分环境检查，但**没有重新运行该组模型结果**；另四项的均值为 9.6 / 8.3%，它也不是六项完整维度的成绩。

因此不能把 6.4 / 5.6% 与 5.78 / 4.56% 接近解释成“已经成功完整复现”，也不能用这份部分记录判断官方榜单有误。第三方报告中的运行、原因和修复为其自述，本站没有复验；其余四个能力维度在该文档中标为未运行。

## 真实问题、版本与现有边界

此前已记录的 [RoboDojo issue #32](https://github.com/RoboDojo-Benchmark/RoboDojo/issues/32)中，提问者担心异常中止回合的分母及 seed 记录难以追溯，并提出在结果中补充；issue 仍开放且未见官方结论，本次没有复现。这个问题与上方第三方把两个**未运行的任务**在其展示均值中按零计入不是同一事件，不能合并其分母或归因。

[RoboDojo 官方固定 README `f57e163`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/README.md)记载 2026-09 的观测单帧差异修正，以及与 RoboTwin 协同调整 RGB 字节通道顺序、需配套指定 XPolicyLab 提交或更新版本；作者称单帧修正后复测多模型结果基本不变。本轮没有核对具体第三方日志所用版本或重跑，因此不能推定本站两段样例受影响、推定所有榜单有误，或将作者对单帧修正的说法自动推广到 RGB 修改。

## 对项目定位的影响

### 步数预算与版本：同一评测的具体争议

- [OpenRUA 团队 2026-11-02 的研究](https://openrua.ai/revisiting-rua)考察 RoboDojo 上的机器人使用智能体，指出控制步数、任务完成判定和是否在测试任务上开发技能会影响结果。其对 RoboDawn 公开的 210 条运行做重计，称 99 条在原设置成功、只有 2 条在原生步数限制内成功，即约 **47.1% 与 1.0%**；这是同一批记录按不同截点重计，并非重新运行或直接测量真机能力。本站没有取得并逐条重算这些运行；[RoboDawn 论文](https://arxiv.org/html/2609.22966)报告完整任务、单次示范时成功率 47.17%，并单独讨论命令预算变化，论文的维度聚合方式与 99/210 的简单比例不可未经核实地等同。
- 同一研究称 Embodied First Exam（EFE）当时将原生步数上限替换为 15,000 动作的技术上限。这个描述**不能不带版本地套用于后续 EFE**：[其合并的 RoboDojo 适配 PR #142](https://github.com/mll-lab-nu/embodied-first-exam/pull/142)的历史说明写过两种模式不采用原生 `step_lim`，技术上限 15,000；[11 月 3 日合并的 PR #520](https://github.com/mll-lab-nu/embodied-first-exam/pull/520)明确将 standard 模式改为智能体自主结束、隐藏成功信号并采用原任务步数，作者注明旧 standard 结果按旧规则评分、privileged 行为不变。其[合并提交 `9dfae86` 的代码差异](https://github.com/mll-lab-nu/embodied-first-exam/commit/9dfae8611326c4f159ebe2211cb9b71a92139406)可见设置步数上限的分支；[11 月 9 日固定提交 `d441015` 的 README](https://github.com/mll-lab-nu/embodied-first-exam/blob/d4410156b8a0a751684b57d6bf1072ed01bcb3e1/tasks/robodojo/README.md)也作相同模式区分，privileged 另有 15,000 动作技术上限。两模式另有墙钟时间限制。无法据此确定每条已发布成绩的运行版本或断言改动由 OpenRUA 文章引起；本站未运行 EFE 或复核历史成绩。
- OpenRUA 还报告，在其自做的 10 任务 × 5 布局实验中，改变为由智能体自己决定停止后，RoboICL 的平均得分从 83.2 降至 63.5；这里是**平均进度分**而不是二元成功率，比较的是该研究者的两组运行，不是论文原报告的逐项成绩。任务结束信号的设计取决于测量目标：自动结束可衡量任务执行进度，但不能同时证明智能体能自主判断完成。作者提出的只使用指定真实可得信息及自主停止是一套协议主张，不代表所有其他测评都无效或所有真实机器人都不可能获得额外传感信号。
- 本站已有的 `align_blocks` 样例恰好展示 200 步未成功、同一轨迹延长到 335 步后成功，因此与上述预算问题可以联系起来；但它来自 SenseNova 的另一份日志，不能用来验证 RoboDawn 或 EFE 的数字。该样例目前不提供这三类研究的系统对照或按版本的榜单记录；此类呈现能否帮助实际读者仍需试用验证，OpenRUA 和 EFE 已经提供相关解释及工具，不能称为本站独有。

“把 RoboDojo 和 RoboTwin 联系起来，并告诉人们如何评测模型”已有官方中文入口和执行工具；在**跑测试、接策略和获取榜单**方面，XPolicyLab 明显比资料库更完整。本站目前已有具体样例及来源，可能适合作为阅读与理解入口，但尚不能声称比官方文档更好，或能帮助用户复现。

值得验证的一道具体任务：给读者论文 Memory 成绩、第三方表格以及本站样例，询问“哪些任务没有运行、两个数字分别是什么、能否说已经完整复现”。原论文和第三方文档已经给出答案，本站是否有更省时的组织方式需要实测；潜在用户的回访、付费与内容更新成本同样未知。

## 2026-11-10：同一模型换控制框架，以及真机任务身份

[OpenRUA 的 uni-robot-agent 论文](https://arxiv.org/html/2611.01560)与[作者交互式报告](https://openrua.ai/uni-robot-agent)提供了与本站 RoboDojo 条目可关联的具体对照。下面都是作者报告，本站未安装或运行，不能仅凭成绩判断其因果机制或现场效果。

| 公开结果 | 测了什么 | 阅读边界 |
| --- | --- | --- |
| Qwen3.8-Flash-Next + RoboProbe：1.90 分；同模型 + uni-robot-agent：31.39 分、25.00% SR | 论文在 RoboDojo 42 项仿真任务上比较框架；主要配置每任务 3 个 seed、每 seed 两种布局，共 252 回合，每回合墙钟上限 3 小时。 | 31.39 是允许部分进度的综合分，不是 31.39% 成功率。它说明结果依赖控制框架及工具，不能说同一基础模型天生只有一个机器人分数；不能从结果单独证明哪项框架机制导致提升。 |
| GPT-6 Astra + RoboProbe：已发表 28.97 分；Astra + uni-robot-agent：51.90 分、46.67% SR | 同一报告引用旧的 Astra–RoboProbe 成绩，也列作者新框架实验。 | 作者注明已发表基线沿用各自协议，不能简单当作完全受控的同条件实验；Qwen 的 31.39 超过的是 **Astra + RoboProbe 的 28.97**，不是超过同一新框架下 Astra 的 51.90。 |
| 作者自建真机 Real Eval：Qwen 53.50、Astra 80.50、π0.5 47.75 | 19 项、五能力维度，各维度 20 分，可给部分进度；双臂平台为 ARX AC one，使用 D405 相机。 | 这是另建的真机测试，不是本站 RoboDojo 的 18 项真机任务，也不是 AA 的 8 项任务；总分不是完整任务成功率。作者的 agent 使用深度，π0.5 和 Dream-1 只用 RGB，π0.5 在同平台微调、其余列出的 agent 为零样本；这些差异使模型能力不能孤立归因。此处未核实每题完整真机试次和逐回合录像。 |

作者按参考 API 费率对上述 RoboDojo **仿真**主实验估算 Qwen 平均约 1.09 美元、Astra 约 21.29 美元／回合；这是各自 252 回合的推算 API 成本，与真机费用、训练成本或 AA 不同任务下的成本不是同一口径。社交平台转述这一结果时容易只保留“成本和名次”，具体可回查[作者成本章节](https://openrua.ai/uni-robot-agent)。

现成工具和使用边界也已有公开说明：[uni-robot-agent 仓库](https://github.com/Open-RUA/uni-robot-agent)提供代码、RoboDojo 接入、运行记录和 dashboard；读取时 README 说明默认 RoboDojo 开启深度、论文 RGB 条件需显式 `--no-depth` 且保留相机标定。README 同时将 ARX One 与 Franka 真机集成标为 coming soon，称公开包尚无受支持的真机连接流程；论文作者做过真机实验不等于当前公开包可直接复现。仓库标 MIT，但依赖、模型和素材许可另行核对；具体功能未安装验证，状态会更新。

[一条公开讨论](https://www.reddit.com/r/LocalLLaMA/comments/1xmyji8/can_qwen_directly_control_the_robot_as_well_as/)以 Qwen 与 Astra 是否能直接控制机器人为问题转述该研究，体现一条实际信息查找线索；发帖者背景和代表性未知，也未证明其需要本站。作者项目页已经解释模型、框架、评分和输入差异，属于对本项目“集中解释成绩”设想的现成替代。可验证的读者问题是：比较 Qwen 和 Astra 时，是否能同时找出各自框架、仿真或真机、分数含义及传感器差异；目前未进行读者测试。
