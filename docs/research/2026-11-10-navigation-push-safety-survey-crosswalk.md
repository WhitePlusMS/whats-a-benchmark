# 移动推物、目标导航与安全巡检：候选及来源交叉核查

调查日期：2026-11-10。由[中文综述表 4](https://castjournals.cast.org.cn/joweb/zgtxtxxb/CN/1322960864705393559)的未完全同名行继续追查；名称检索仅覆盖本地 `content/benchmarks` 文件名及既有 `docs/research` 文本，不能证明没有别名、关联条目或其他人的产品。以下均是候选研究，不是新增正式评测条目，也未运行仿真或联系开发者。

## Bench-Push：导航与主动推箱不是同一成功率

[Bench-Push 论文](https://arxiv.org/html/2512.11736)及[固定提交 README](https://github.com/IvanIZ/BenchPush/blob/e9f865bee8d7a27ce2330112d6a261b42f3863ae/README.md)给出四类环境：可移动障碍迷宫、船舶冰区导航、箱子递送、区域清理。它们支持简化 2D，部分支持 3D；论文说明 2D 船舶模型不模拟流体动力。该基准与移动机器人、推箱物流研究相关，但不等同于真实仓库 AMR 场景、安全认证或本站 [R2R-CE](../../content/benchmarks/r2r-vlnce.json) 的语言路径跟随任务。

论文的操作任务成功得分是完成子任务数除以对象总数：推到目标 2 个箱子、共 3 个箱子时得分是 2/3，**不是 66.7% 的试验全部成功率**。它还单列路径效率和交互努力；论文明确操作效率近似下界不保证一定位于 0–1。若只做统一榜单或统一称“成功率”，会丢掉不同分母和指标方向。

不能因为主体是模拟就漏掉论文已有的物理实验：作者对 Maze、Box-Delivery 用 TurtleBot3 Burger、顶置摄像头和 3D 打印箱子做真机对照，每种配置分别为 **20 个仿真 episode、3 个真机 episode**。论文报告部分指标趋势相近，但 3 次/配置规模很小，不能据此证明可迁移到任何工业现场；真机对照也不覆盖四类环境全部任务。本次未复核轨迹、模型权重或实际置信区间。

[已有中文简介](https://www.selectdataset.com/dataset/7a8507ab64a1da42622122e8bd64d2ec)及[中文论文介绍](https://damodev.csdn.net/6986138a54b52172bc5a537a.html)已经覆盖任务、指标及部分实机设置，不能称中文资料空白；介绍的全部事实未逐项审计。固定仓库 README 标注 MIT 代码许可，不自动等于模型权重、素材或依赖均可同条件再发布。

## GOAT-Bench：多目标导航与开发者困惑

[GOAT 官方固定提交 README](https://github.com/Ram81/goat-bench/blob/74c41d19d4a4c3608d1575b512087b5a529aee0e/README.md)描述每个回合顺序寻找 5–10 个目标，目标可由类别、文字描述或图像指定；每个子任务要求在目标 1 米内主动停止，每子任务最多 500 步。这是 Habitat 室内仿真中的开放词汇目标导航；本站 R2R-CE 是按路线语言到目标并停止，任务和终止条件不相同，即使都报告 SR/SPL 也不能混排。

公开需求线索是具体开发工作，而非本站市场规模：[home-robot #527](https://github.com/facebookresearch/home-robot/issues/527)的提问者不清楚多个分支、场景数据和任务数据版本之间如何对应；之后同一提问者记录自己使用的分支及数据入口，本次未验证该办法对其他版本有效。[GOAT #34](https://github.com/Ram81/goat-bench/issues/34)另询问重复目标与指标实现；一位评论者解释相关图像索引和不同查询图像，但不能把该回答推广为对所有重复目标或指标问题的官方结论。[3D-Mem #14](https://github.com/UMass-Embodied-AGI/3D-Mem/issues/14)报告使用第三方方法评估 GOAT 时偶发对象 ID KeyError；这是该方法集成中的自报现象，不证明 GOAT 基准本身存在同一缺陷。

## HomeSafeBench：版本改变导致规模和成绩不可简单衔接

[论文 v1](https://arxiv.org/html/2509.23690v1)报告基于 VirtualHome 的 **12,900 个样本**，另选 **1,580 个样本**作较小实验子集；中文综述表中 12,900 与 v1 一致。[论文 v2](https://arxiv.org/html/2509.23690v2)及[作者仓库](https://github.com/BITHLP/HomeSafeBench)则描述环境划分后的 **3,400 个训练任务、1,000 个测试任务**。v2 另有筛选和重放后的 3,158 条训练轨迹。12,900、4,400 和 3,158 分别属于不同论文版本或不同对象，不能视作同一集合的三个互相可换计数；未逐样本建立 v1/v2 的对应关系，不能断言新版只是旧版简单删减或互不重叠。

该任务是智能体在模拟家庭中自主探索，并基于第一视角报告火灾、触电、坠物、绊倒及儿童安全风险；它与既有[工业巡检研究](2026-11-10-industrial-asset-eqa-and-inspection.md)相关，但不是实际厂房、设备检修或现场机器人验收。v1、v2 的数据与实验设计都需分别追溯，不应将跨版本 F1 直接相减作为模型进步。数据卡标 CC BY 4.0、代码仓库标 MIT，VirtualHome 等外部组件应另核许可；本次未下载或验证数据文件。

## Verti-Bench：越野控制不是语言导航

[官方项目](https://people.cs.gmu.edu/~xxiao2/Research/Verti-Bench/)及[代码仓库](https://github.com/RobotiXX/verti_bench)描述 100 个环境、每个环境 10 组起终点，共 1,000 个越野导航任务；作者用 Project Chrono 仿真不同车辆及地形，测试传统规划、强化学习和混合系统。它提供车体、地形和起点目标设置，关注崎岖地形通过，不能视为真实越野车辆成绩或直接和 R2R-CE 的语言任务排名。

## 2026-11-10：任务驱动定位、无人机与主动问答

本地 `content/benchmarks` 和 `docs/research` 以 `TaskSLAM-Bench`、`BEDI`、`EXPRESS-Bench` 等名称检索未找到独立同名条目；未命中不等于不存在别名或相关功能，本次只调查，不自动新增产品数据。

### TaskSLAM-Bench：重复到位和完整度

[TaskSLAM-Bench 论文](https://arxiv.org/html/2409.16573)比较不同定位与建图方法支持机器人反复经过任务点的能力。论文的 Gazebo 模拟场景包含虚拟仓库；真实实验在办公室，分别设约 45 米、6 个目标点和约 120 米、12 个目标点的路径。**虚拟仓库结果不是仓库真机运营数据**，两条真实路径也不能代表所有工业环境；场景表没有在可读文本中逐行标明真仿归属，仿真场景总数暂不确认。

其 `precision` 衡量多轮到达同一目标点时位姿相互接近程度，`accuracy` 衡量其相对目标的误差；机器人可以重复停在接近同一位置，却存在系统性偏移。论文每场景进行五轮：某任务点需五轮均到达才记为完成，`completeness` 是满足该条件的任务点比例，而不是五轮所有单次到达次数的成功率。论文实际实验使用 TurtleBot 2 与相应雷达、相机及标记测量；[固定仓库 README](https://github.com/ivalab/task_driven_slam_benchmarking/blob/d5ccab7d370bb0729c834b9df3c4747b4488593f/README.md)提供导航实验入口。本站 [R2R-CE](../../content/benchmarks/r2r-vlnce.json)记录语言路线任务和单次仿真结果，两者相关但模型输入、任务与分母不同。本次未运行 ROS、复算结果或在真实车间测试。

### BEDI：真实素材与真机闭环分开

[BEDI 论文](https://arxiv.org/abs/2505.18229)、[固定仓库 README](https://github.com/lostwolves/BEDI/blob/97cd4d7906ca3c8f1e73a001c5cc30006dcd8661/README.md)描述无人机感知、决策、动作生成，以及虚拟场景交互接口。README 所述静态图像 1.0 包括 154 张感知图对应 2,740 个问题、30 张决策图对应 357 个问题；它们是问题与图像数量，不能写成无人机执行次数。另有基于真实飞行视频帧构建的动态场景和仿真接口；**真实视频帧不自动证明被评模型实际控制真机飞行**。

[作者 Hugging Face 数据入口](https://huggingface.co/datasets/GuoMN/BEDI)本次自动预览显示 36 行，数据卡显示未填写；这只是该预览视图的数量，不证明整个仓库只有 36 张图，也不能与 README 的静态题数直接判定冲突。各路径、完整数据和适用许可本次未下载或核验。它可与[仓储无人机研究](2026-11-10-warehouse-dispatch-aerial-benchmarks.md)中的 WareFly-VLA 对照，但拍摄场景、任务、数据和闭环程度不同；两者都不能由公开分数推断现场巡检安全性。

### EXPRESS-Bench：答案要结合观察依据

[EXPRESS-Bench 论文](https://arxiv.org/html/2503.11117)在 Habitat 中研究智能体边探索边回答问题，包含 777 条探索轨迹和 2,044 个问题—轨迹对；这些不是 2,044 次真机作业。它与本站 R2R-CE 的导航部分相关，但目标是回答关于环境的问题，不是同一项路线跟随基准。

论文的 EAC 方法让视觉语言评判结合问题、参考答案、回答和最后观察画面：答案正确度为 1–5 分，依据相关性取 0、0.5 或 1，两者相乘后再归一化汇总。`C` 因而是带依据权重的分数，不是二元问答准确率；`C*` 则去掉该依据权重，不能将两列直接当成同一种成功率。论文另报路径效率和终点距离；其自动评判和运行模型/设置也影响结果，本站未独立重评分数。[官方项目页](https://hcplab-sysu.github.io/EXPRESS-Bench/)已提供任务案例及方法介绍，[AgentCanvas 现有适配文档](https://jianzhou0420.github.io/AgentCanvas/pages/developer-guide/nodesets/env/express.html)也组织数据、环境和运行流程；这些不是本文对外站运行能力或每项得分的验收。

三项分别反映路径重复性、空中素材理解/仿真交互、环境探索问答；真实数据、物理平台、模型输出及执行闭环必须逐项注明。它们提示一些评测内容可能值得读者检索，但当前没有这些开发者的本站使用反馈或付费数据。

## 产品判断与未完成工作

从同一中文综述向上游追溯已经看到：**同名不代表同版本、同叫成功也有不同分母、真机和仿真需要标明单独试验规模**。真实 issue 显示少数开发者关心数据与运行条件，但已有官方仓库、论文、中文介绍和社区答疑；这些案例不证明本站相对优势、使用规模或付费意愿。下一步可围绕具体任务比较用户能否在现有来源与本站草稿之间更快找出版本、数据集和试验条件，尚未开展用户对照。
