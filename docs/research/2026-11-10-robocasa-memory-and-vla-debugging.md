# RoboCasa-Mem：记忆评测、真机边界和开发者排错问题

核查日期：2026-11-10。仅阅读本站文件和公开来源；未运行仿真、策略或实体机器人，也未验证外部使用者身份。

## 与本站已有内容的关系

本站已有 [RoboCasa365](../../content/benchmarks/robocasa365.json) 家庭移动操作仿真和在其厨房环境中进行搜索、检查、实验的 [RoboQuest](../../content/benchmarks/roboquest.json)。另有 [RoboDojo](../../content/benchmarks/robodojo.json) 的 Memory 维度，以及 [CALVIN](../../content/benchmarks/calvin.json) 连续操作。对现有 benchmark JSON 和研究文档按 `RoboCasa-Mem` 与论文编号搜索，未发现同名独立记录；名称搜索不能排除别名或其他站外页面。

[RoboCasa-Mem 论文](https://arxiv.org/html/2611.06475)以 RoboCasa 仿真为基础设计九项家庭移动操作任务，分为环境记忆和过程记忆。例如 SweetCup 允许策略自己选择向哪杯加糖，溶解后依据该回合此前行为确定哪杯应被选中；HeatAndInspect 则要求加热后执行检查，记得返回关闭炉灶。后者是**仿真中对未完成任务的记忆与切换**，不能由成功率推断真实炉灶或工业设备控制安全。

任务时间长和需要记忆有关，但并不相同：如当前画面已足以决定下一动作，长步骤本身不证明必须保存历史。RoboQuest 专注主动搜寻、检查和测试以取得隐藏信息，RoboCasa-Mem 专注历史信息不再可见后的决策；二者都存在移动操作，具体任务和判定仍不同，不能混排成绩。[现有记忆评测对照](2026-11-09-robot-memory-benchmark-crosswalk.md)另有 LIBERO-Mem、RoboMME 和 MIKASA-Robo-VLA，它们也不是 RoboCasa-Mem 的同一评测。

## 数字如何解释

- 作者称使用规则专家生成并筛选每任务 200 条成功示范，共 **1,800 条**；这是训练示范，不是人工遥操作或模型评测成功次数。论文称各任务在相同的 50 个留出场景种子上评估，且所比较方法都使用相同任务示范训练；评测结果不应称为未经任务训练的零样本成绩。
- 论文报告 HMAP 九任务宏平均成功率 **24.2%**、对照的 π0.5 为 **16.2%**；这是作者设定和训练下的仿真结果。HMAP 同时包含高层规划与几何增强，不能把整体差异全归因于记忆模块。[论文消融](https://arxiv.org/html/2611.06475)提供分组件比较，但未在本站复现。
- 在 HeatAndInspect 和 FillAndRetrieve 两项交错调度任务上，论文表中各方法完整任务成功均为 **0**，阶段分数则可能非零。阶段完成率是分阶段成功率的平均，不等于完整任务成功率；论文指出 SugarCount 各加糖阶段适用的回合数可能不同，也不能简单视为同一分母。
- 真机是另一个独立实验：AgileX Cobot Magic 平台上的单项物品运输，每种方法 **10 次**。论文表中 π0.5 和作者方法分别将物体放入正确容器 **2/10 与 8/10**；作者方法“移动并放下”是 **9/10**，对应的指标不同。不能把这组结果当九个仿真任务都完成了真机测试，或当作现场稳定性保证。

## 公开程度与现有替代

[作者项目页](https://sihhangchen.github.io/RoboCasa-Mem/)已有任务说明、演示、成绩和真机部分；[固定提交代码仓库](https://github.com/SiHhangChen/RoboCasa-Mem/tree/2c7d498e589d1a5a62b5b30c9d786513fa86bfa2)提供[中文 README](https://github.com/SiHhangChen/RoboCasa-Mem/blob/2c7d498e589d1a5a62b5b30c9d786513fa86bfa2/README.zh-CN.md)、仿真评测接口、种子和安装说明，代码标注 MIT。该提交自述为 `0.1.0rc1`，去除真机集成后仍待已安装 wheel 验收；仿真源码、资产、模型实现和权重须另外安装。仓库链接 ModelScope 数据，本次数据网页未返回可读文件清单，没有下载或验证全部资源及数据许可；代码 MIT 不能直接延伸到模型、数据和视频。

此外已有中文的 [arXivDaily 论文介绍](https://www.arxivdaily.com/papers/2611.06475)和 [研究汇总目录](https://github.com/avanturist322/awesome-memory-vla)。因此“中文解释记忆评测”及论文目录也不是无人覆盖。它们与作者站的覆盖深度、用户使用量和正确性未做系统比较。

## 一个相关但不同的实际问题

[机器人社区提问](https://www.reddit.com/r/robotics/comments/1wb6i2y/error_analysis_in_vla/)中，一位使用者自述在 LIBERO 测试微调的 SmolVLA：某个抓取任务在移除其他物体、改变推理时间或随机种子时表现变化，询问如何系统定位失败并改善鲁棒性。有评论推荐一个诊断评测，提问者表示会看。

这是公开的个体自述，未提供足够信息证明哪种因素导致失败；它也不是 RoboCasa-Mem 用户，更不是记忆故障的证据。它提示产品可能需要区分“找一个评测”与“我已经运行模型，想排查自己的失败”两个工作：后者可能需要代码、重复实验和运行日志，不一定能由一篇目录介绍解决。是否有人需要本站提供这种帮助、是否愿意持续使用或付费，都还未验证。

可用上述材料测试具体阅读任务：让机器人开发者判断 SweetCup 的目标何时确定、阶段分数与完整成功率有何区别、真机涉及几项任务，以及去哪里运行评测；对照作者中文 README、项目页和既有目录，记录正确率及耗时。此处只是验证方案，尚未实施。
