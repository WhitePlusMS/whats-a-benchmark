# 真实 Benchmark 样例展示架构审查

审查日期：2026-09-23  
范围：只读检查现有 schema、展示组件、内容生成与发布校验，以及 GSM8K、ARC-AGI-2、IFEval 三条样例记录。本次未修改正式内容或代码，也未联网核查任何数据集。

## 结论

现有架构已经把内容源文件、生成数据和前端展示分开，新增文字、代码、选择题、图片或网格样例不需要改动基本加载流程。要支持音频、视频和其他真实数据附件，主要缺口是媒体资源还没有进入严格 schema、附件引用清单和构建产物核验；样例数量也被 schema 固定限制为每项最多 3 条。

建议保留“一项 benchmark 一个 JSON、构建时校验、前端按需加载”的方式，只扩展样例类型、来源证据和附件清单。对于依赖终端、桌面软件、网页或游戏环境的评测，展示官方数据中的真实静态记录片段，并明确标注截取字段和原始出处；不要把网页卡片包装成完整环境复现。

## 当前实现与观察

- `src/content/schema.ts` 使用严格对象校验。样例类型目前是 `text/code/choice/grid/image`；图片字段只有本地相对路径与 alt。每条样例都有 `raw`、`source`、`license`、`split` 和 `excerpt`，但 schema 无法证明这些字段与上游数据一致。`sampleSet.samples` 固定 1–3 条。
- `SampleViewer.vue` 从 `public/samples/<id>.json` 按需取数据，可读任务与原始记录；媒体渲染目前只有 `<img>`。展示文本与 raw 分离，`explanation` 被标为本站解读，网格操作说明也明确标注为本站整理。
- `ArcTask.vue` 把已保存的二维矩阵画成 SVG，并隐藏测试输出直到用户展开答案。它展示的是原始矩阵的静态可视化，不模拟 benchmark 的完整推理或评测环境。
- `content-pipeline.ts` 只将许可文件和图片列为样例附件；校验文件存在且非空、路径实际解析仍位于 `content/assets` 内。构建会复制被引用资源，但没有单文件或整站媒体体积上限。
- `verify-public-output.ts` 对样例 JSON 和 `favicon/logos/licenses/images` 做实际磁盘清单核对。新增音视频目录若不同时更新清单过滤规则，就无法检查遗漏、残留或未审素材。
- `postbuild.ts` 现有检查覆盖静态路由及基准页面节点，不核验样例媒体 MIME、文件大小或浏览器可播放性。
- `docs/CONTENT_MAINTENANCE.md` 已规定“公开不等于可任意转载”、限制/私有/未知数据不能发布、采集候选不得直接覆盖正式内容，并记录了当前不支持音频/视频。

现有真实记录形态有差异：GSM8K 的 JSONL `question/answer` 原文在 `raw` 中，同时有可读 prompt/answer；IFEval 保留 `prompt`、`instruction_id_list`、`kwargs` 等源字段，展示重点是约束元数据而非唯一答案；ARC-AGI-2 用 `raw` 保存记录，并把网格映射成 SVG。这些形态说明应允许源字段原样保留并按明确的展示适配器呈现，不应要求所有数据压成同一种题面结构。

## 建议的最简扩展

### 1. Schema：将“内容类型”和“媒体附件”分开

保留现有 `type` 作为主任务呈现类型，增加 `audio`、`video`，以及必要时的 `record`（只展示源记录字段）类型。增加可复用的 `assets` 数组，每项采用严格的媒体联合结构：

```ts
type SampleAsset =
  | { kind: "image"; path: string; alt: string; caption?: string }
  | { kind: "audio"; path: string; caption?: string; transcript?: string }
  | {
      kind: "video";
      path: string;
      poster?: string;
      caption?: string;
      transcript?: string;
    };
```

这里的 `path`、`poster` 应只允许 `content/assets` 下的相对路径，并按类型限制扩展名；不要允许任意 URL 绕过本地附件审查。视频字幕若以独立 WebVTT 文件维护，可将它列为受校验附件，并通过 `<track kind="captions">` 引用；`transcript` 可先用内联原文，较长时再改成受控文本附件。保留旧 `image` 字段是否迁移为 `assets` 属于正式实施决策；建议统一迁移，避免两套并行媒体模型。

每条样例的证据字段建议最小增加 `recordId`（官方稳定记录标识；可与现有 `id` 合并但须说明语义）和 `source` 指向具体记录/文件/官方查看页。当前 `source` 已存在；手工录入时应要求精确到记录或明确标注它是数据文件来源。继续保留 `raw` 原始字段、`split`、`excerpt`、`license`、`licensePath`。本站解读只能留在 `explanation`，不能被拼接进 `raw` 或冒充 benchmark 原文。媒体还应有来源记录：可先复用样例级来源与许可，若一个样例多个附件来源/许可不同，再为每个 asset 加 `source`、`license` 和可选署名字段。

### 2. 展示：使用原生、可访问的媒体控件

- 图片使用 `<figure>`、`<img alt>` 和独立 `figcaption`；alt 描述视觉信息，caption 用于出处或展示说明，不要把两者混作一条说明。
- 音频使用带 `controls` 的 `<audio>`，默认 `preload="none"`。逐字稿/听觉描述作为可见文本或可展开文本提供，且与官方 transcript 和本站说明区分。
- 视频使用带 `controls` 的 `<video>`，默认 `preload="metadata"`，提供 `poster`、字幕 `<track>` 和可访问的 transcript；字幕没有核实或官方不存在时，不得自行生成后当成原始标注。字幕语言应明确编码。
- 给媒体控件提供可理解的标题/上下文、键盘操作和可见焦点；加载失败时提示并保留原始来源链接。不要自动播放。
- `record` 或现有 `raw` 视图继续作为兜底，使未知结构仍能如实查看，而非编造一个“交互任务”。

### 3. 附件管线：检查引用、路径、格式和体积

扩展 `referencedAssets()`，纳入每个媒体文件、poster、字幕及文本附件；复用真实路径必须位于 `content/assets` 内的防护。对应更新构建复制与产物清单验证，确保只有已审核、实际引用的附件被发布。

静态站没有流媒体转码或按需服务端处理。建议先制定保守且可配置的发布预算：逐文件上限、单个样例总媒体上限、全站新增媒体总量上限；超限文件不进入 `dist`，引导改为官方链接或经确认可用的轻量片段。实际阈值应以 GitHub Pages 约束、仓库体积和移动端体验为依据，在实施时核实当前官方限制后写入文档，不在本审查中猜一个数字。音视频用压缩过的真实片段或官方提供的预览文件，并披露它是片段；不为了展示而重新剪辑/转码成可能改变 benchmark 内容的版本，除非确实需要且保留原件、变换记录和许可依据。

### 4. 真实性与发布门槛

绝不生成题目、答案、输入、字幕、转录、网格或“示例图片”。每条正式记录必须可追溯到官方数据文件/官方查看页中的具体样本；采集时原样保留源对象，展示字段只做可解释的字段映射。若只展示长记录中的一部分，`excerpt` 必须为真，并记录截取边界；若媒体来自官方预览或源仓库文件，保留对应路径/记录 ID 与许可。缺字段时留空或不展示，不能用看似合理的文字补齐。

仅凭 `availability: public` 仍不能证明题面、媒体、答案和派生字幕都允许本地再发布。正式流程需逐样例核实许可和署名范围；官方只允许在线查看、禁止转载或无法确认时，保留官方入口，不复制附件。校验器能检查结构、路径、格式、大小、引用和证据字段是否填写，不能自动证明内容真实或有转载权；这部分必须保留人工对照官方原件的审查步骤。

## 验收点

1. 既有 GSM8K、IFEval、ARC-AGI-2 原样例仍通过校验，既有展示、答案折叠和 ARC 网格正确。
2. 图片、音频、视频、字幕和 transcript 均能从静态产物加载；音视频不自动播放，控件可键盘操作，缺失媒体给出错误提示。
3. 路径穿越、指向仓库外、错误扩展名、空附件、超大小预算、未被任何发布样例引用的媒体都会被拒绝或从发布清单排除。
4. 许可限制/未知状态不能借媒体 asset 字段绕过发布门槛；每个附件能追溯到官方来源与适用许可。
5. 较长样例集合能通过校验和导航；保留合理总量/文件体积约束，不由当前每项最多 3 条的任意值卡住。
6. 对终端、桌面、网页、游戏等环境型 benchmark，页面明确显示来源记录片段和限制，不声称复现了官方完整运行环境或评测结果。
7. 真实浏览器检查至少覆盖桌面与手机布局、媒体播放/字幕、键盘访问、加载失败和答案/原始数据切换；构建测试与浏览器验收分别记录。
