## 1. 项目背景与当前状态

项目是评测资料展示站，仓库为 https://github.com/WhitePlusMS/whats-a-benchmark 。每个评测通常在 `content/benchmarks/<id>.json`，样例位于 `sampleSet.samples`，需要图片、视频时使用 `content/assets/` 对应目录及许可文件。项目展示什么任务、数据是什么、用户可以怎样访问，而不只是列榜单成绩。

用户的整体目标是：先核对并去除具身评测重复案例，再补确实缺少的验证/测试数据和可使用的图片视频；然后核验 LLM 等非具身评测是否有数据。要求真实、来源可查、不要重复、不能夸大。**整个剩余任务都由你接手**：具身及全部非具身评测均在范围内。本地智能体已暂停，不再与之分工；先核对现有内容，不要重复新增 FrontierScience 或任何已有案例。

## 3. 如何查找与判断

1. 先完整阅读本任务涉及的 JSON、相关 schema / 展示组件、现有清单及仓库约束。以官方论文、官方仓库、官方数据卡、数据文件和评测脚本为主；第三方转换集必须标明是谁转换、固定版本和与官方版本的对应关系。不要只依靠搜索摘要。
2. 对具体候选先查本站是否已有同一题目、ID、原始行、轨迹或同源媒体；同一题不同写法、同轨迹不同转换也可能重复。不能确认时说明不确定，不作强断言。不同任务实例或成功/失败的不同试次不是当然重复。
3. 可在隔离临时目录小范围下载公开文件或解压指定成员，检查数据结构、具体记录、划分、图像或视频；记录固定提交 / 数据集 revision、文件路径、行号或 ID、下载时间、文件大小和 SHA-256。保留原始事实；不能把训练演示、示意图、模板、模型生成内容或榜单汇总冒充验证集/测试集。
4. 明确区分“可访问”“许可允许转载”“作者请求不公开题目”“仅可登录后使用”“没有找到”“未公开/私有”。例如当前 GPQA 和 HealthBench 已有作者不在线公开样例的请求，Video-MME 的转载有条件；不要重新发布这些题或视频，也不要绕过访问控制。上游原始图片、音视频、题目可能与数据集代码采用不同许可。
5. 如有真实可展示样例：遵循现有 JSON 模式，记录任务输入、必要答案或动作、原始来源、精确 split、许可、节选与解释；说明中文整理及媒体是否为同一条记录。图片/视频尽量使用可确认来源且可复用的真实素材；注明是否裁剪、转换或合成及帧率。无法确认成功、评测结果、分数或对应关系时明确不推断。
6. 需要授权、找不到或无法独立确认时就如实记录；任何权限限制不可绕过，不需要为了达成覆盖率而编造。不要上传密钥、Cookie、个人数据、整套大数据或下载缓存。
